# Scientific evidence for repository context retrieval

The useful distinction is between representation, retrieval policy, and the interface presented to an agent. A paper demonstrating one does not automatically validate the others. The studies below motivate experiments; their numbers are not directly comparable across models, workloads, or accounting methods.

| Study and publication status | Method and evaluated workload | Reported finding | Consequence and limitation for graf | Reproduction material |
| --- | --- | --- | --- | --- |
| [Agentless](https://arxiv.org/html/2407.01489v2), 2024 manuscript; [FSE 2025 publication](https://lingming.cs.illinois.edu/publications/fse2025.pdf) | Hierarchical localization, declaration skeletons, repair, validation; SWE-bench Lite | A simple staged workflow is competitive with contemporary agents | Test file → declaration → source expansion. Results concern the whole repair pipeline, not isolated retrieval superiority. | [Author implementation](https://github.com/OpenAutoCoder/Agentless) |
| [Repoformer](https://arxiv.org/html/2403.10059v1), ICML 2024 | Learned selective retrieval for repository code completion; RepoEval and related completion datasets | Retrieval can be unnecessary or harmful; selective policies improve the accuracy–latency tradeoff | Test retrieval gating. The largest speedup settings have accuracy tradeoffs; indexing is assumed complete and serving uses parallel branches. Do not translate latency into total-compute savings. | [Author implementation](https://github.com/amazon-science/Repoformer) |
| [LocAgent](https://aclanthology.org/2025.acl-long.426/), ACL 2025 | Heterogeneous code graph plus search and traversal; localization and downstream repair | Ablations support both lexical search and graph traversal | Retain a lightweight relationship baseline. The reported approximately 86% cost reduction also changes to a fine-tuned model, so it is not a graph-only causal effect. | [Author implementation](https://github.com/gersteinlab/LocAgent) |
| [RepoGraph](https://arxiv.org/abs/2410.14684), 2024 manuscript | Repository structure added to software engineering systems; SWE-bench and CrossCodeEval | Structural navigation improves the evaluated systems | Include graph-assisted retrieval as a control. Improved resolution does not establish lower indexing cost, memory, or total token use. | [Author implementation](https://github.com/ozyyshr/RepoGraph) |
| [SWE-agent](https://papers.neurips.cc/paper_files/paper/2024/file/5a7c947568c1b1328ccc5230172e1e7c-Paper-Conference.pdf), NeurIPS 2024 | Purpose-built agent-computer interface; SWE-bench and HumanEvalFix | Interface design materially affects agent behavior and performance | Compare bounded search output and progressive viewing while holding retrieval fixed. Historical resolve rates are not current model baselines. | [Author implementation](https://github.com/SWE-agent/SWE-agent) |
| [LongCodeZip](https://arxiv.org/html/2510.00446v1), 2025 manuscript; author repository identifies ASE 2025 | Function selection, block pruning, token-budget optimization; completion, module summarization, RepoQA | Up to 5.6× context compression on evaluated tasks | Test selection under explicit budgets. Include compressor inference and preserve source evidence; this is lossy selection, not lossless code encoding. | [Author implementation](https://github.com/YerbaPage/LongCodeZip) |
| [RAPTOR](https://arxiv.org/html/2401.18059v1), 2024 manuscript | Recursive clustered summaries and multilevel retrieval; NarrativeQA, QASPER, QuALITY | Multilevel summaries improve document QA; selected retrieval searches across tree levels | A candidate for product/architecture docs. It is document-QA evidence, not a code-repair or incremental-update result; summaries require generation. | [Author implementation](https://github.com/parthsarthi03/raptor) |
| [GraphRAG](https://arxiv.org/abs/2404.16130), 2024 manuscript | Entity graph and community summaries; corpus-wide sensemaking | Better comprehensiveness/diversity than the evaluated naive RAG baseline | Include global architecture questions. LLM-derived text graphs differ from deterministic code dependencies. | [Microsoft implementation](https://github.com/microsoft/graphrag) |
| [CodeGrep](https://arxiv.org/html/2608.05886v1), August 2026 preprint | Trained 14B retrieval agent injected into a frozen OpenHands agent; SWE-bench Verified | Own-resolved-set tokens fall 19%; paired solved instances fall 15%; overall resolution rises 1.2 percentage points | Precision can matter more than candidate volume. In this setup BM25 injection hurts. Results do not establish the same effect for another agent or a general precision threshold. | Training/integration described in paper; not reproduced here |
| [FastContext](https://arxiv.org/html/2606.14066v1), June 2026 preprint | Specialized explorer returns compact file-line evidence; Mini-SWE-Agent on three benchmarks | Up to approximately 60% reduction in main-agent tokens | Investigate compact evidence handoff. Explorer internal calls are excluded from the headline; appendix separately audits overhead. Total-system token and monetary savings differ. | Protocol and appendix in paper; not reproduced here |
| [Agent Retrieval Bench](https://arxiv.org/html/2607.24882v1), July 2026 preprint | 427 samples, 25 repositories; tests, comment context, traces, edit consequences, no-gold cases | Different families win different metrics; RepoMap leads budgeted context yield at 8K in that evaluation | Use workflow-specific and budget-specific metrics, including insufficient evidence. File relevance is not proof of completed-task success; scale and task distribution constrain generalization. | [Author benchmark](https://github.com/eyuansu62/agent-retrieval-bench) |
| [CoIR](https://aclanthology.org/2025.acl-long.1072/), ACL 2025 | Diverse code-information retrieval datasets and tasks | Code retrieval remains difficult across evaluated models | Useful retrieval sanity checks, but chunk similarity benchmarks cannot replace repository task evaluation. | [Author benchmark](https://github.com/CoIR-team/coir) |
| [Context compression study](https://arxiv.org/abs/2604.13725), April 2026 work-in-progress preprint | Eight methods across text, latent, and visual compression; completion and generation | Some compressed contexts improve reference metrics and reduce latency | Explore only after a strong retrieval baseline. BLEU gains are not execution correctness; latent and visual methods can require compatible models. | Methods and evaluation described in paper; not reproduced here |

## Strength of the inference

There is evidence for hierarchy, selective retrieval, structural relationships, and interface design. There is no controlled head-to-head result here establishing that the proposed graf combination beats the pinned Graphify version. The 2026 papers are treated as preprints, and this project does not reproduce their training or headline results.

The working hypothesis is that cheap lexical/symbol lookup, optional semantic search, and targeted relationship expansion can complement each other. Architecture summaries and executable source excerpts serve different needs. A tree is itself a restricted graph; symbol reference tables also encode relationships. The engineering question is which relations to maintain and retrieve, rather than whether all graphs should be eliminated.
